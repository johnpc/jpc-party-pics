# State machines

Every mode, phase or status in the app is listed here with its single owner.
Rule: **one mode, one owner** — a discriminated union (or enum-like string)
written in exactly one place; components and other hooks derive from it and
never write a parallel flag.

`npm run check-state-machines` keeps this table honest: every row's owner file
must carry a `// @state-machine <id>` marker, every marker must have a row,
every cited test file must exist, and any source file that declares a
status-shaped type or a boolean `useState` must be mentioned on this page.

## Bugs the conversions removed

- **Camera success flash raced later uploads.** `setTimeout(() => setStatus("idle"), 1500)` was fire-and-forget: a second capture started inside the window was knocked back to `idle` mid-upload (button re-enabled, no "Uploading..."), and the timer could fire after unmount. The flash is now an effect keyed on the phase, so any new phase or unmount cancels it.
- **Camera permission denied was silent.** The stream flag stayed `false` with a black video and no message; `denied` is now a state with an explanatory alert.
- **Retry button that did nothing.** The hero showed "N failed" + Retry for items whose retry budget was spent, but `retryFailed` filtered them out. Failures are now split into retryable vs exhausted; Retry only appears when it can act and exhausted items say "please re-select".
- **Stale album-name validity.** `isValidPartyName` was a stored flag computed at keystroke time, so typing "Demo" before the album list loaded left the button enabled (the old e2e step "I wait for albums to load" worked around it). Validity is derived every render; a second submit while one is in flight is ignored.
- **Lightbox kept a stale copy.** The open image was an object snapshot; after another guest deleted it, forward/back computed `images[-2]` and closed the modal by accident. The lightbox now stores only the key and derives the image.
- **Two counters that had to agree.** `activeUploads` and `inFlightIds` tracked the same thing; the set is now the only record.
- **CopyLink timers leaked.** Each click armed an uncancelled `setTimeout`; a re-click reset early and an unmount set state on a gone component.

## Known gaps (documented, not hidden)

- `uploadQueue.ts` persists `progress` as free-form numbers; the phase start values live in `uploadItemState.ts` but a stale IndexedDB row from an older build is accepted as-is.
- The fake backend's `FakeStore` is test infrastructure, not a UI machine; its create/delete listeners are the fake's stand-in for AppSync subscriptions.
